- Parity after redeploy: an existing Cloud-Init VM is unchanged (key, MAC, IP, conditions).
- G15: LinuxPrep VM, power off, add an interface, power on → no second guest customization; the without-NICs hash is unchanged and the legacy hash is refreshed.
- G2: a running VM with an interface on a nonexistent network stays running with `VirtualMachineNetworkReady=False/ProviderPending`; power-off succeeds; power-on stays blocked (`PowerStateSynced=False`); removing the interface unblocks power-on, the remaining adapter keeps its key/MAC/IP, and the pending NetOP CR is deleted.

### Open issues and decisions recorded during implementation

- Matching (T014/T018): a not-ready provider resource's last-reported attachment is used as identity evidence. Ambiguous legacy interfaces fall back to the positional zip (Q5), so some mutable-network cases that `MapEthernetDevicesToSpecIdx` used to leave unmapped are now mapped by position; tests are labeled "Spec 017 T018". `MatchPositional` + a differing Ready target is classified `Replacement`, but the planner never turns a positional match into an attachment Edit (replacement.md); T026 must keep that rule.
- Orphan-CR claims are computed on every pass (previously only powered off with `MutableNetworks`); the planner still only acts on them powered off with `MutableNetworks`.
- With `VMNetworkUnitNumbers`, the planner places additions at the declared unit number (required for convergence; today's paths never set it).
- The resize path now applies network changes without `MutableNetworks`, matching the update path (plan.md).
- NIC tuning (T019) follows the shared match. Reordering NSX-T/VPC interfaces no longer moves tuning between adapters; a VM reordered before upgrade has its tuning moved back on the first reconcile (may report `PowerOffRequired` while running). A new adapter gets device-level tuning in the Add and its ethernetN ExtraConfig on the next pass.
- Readiness counts any unclaimed adapter (including one added outside VM Operator) as not converged, so bootstrap is skipped on a running VM until it is removed at the next power-off.
- `filterNoRequeueErr` now filters any error containing a `RequeueError`, consistent with its existing `NoRequeueError` handling; a real error joined with a requeue no longer emits a failure Event.
- Retirement now runs in any power state without `MutableNetworks`; after upgrade, unreferenced VM-owned provider CRs with no adapter evidence are deleted. A NetOP CR with no external ID whose only evidence is a shared backing is retained as `AttachmentAmbiguous` (T028).
- G15 edge cases (AC23, owner decision): a static interface without nameservers pulls Supervisor DNS into the global settings, and raw Sysprep templates that render NIC data, both change the without-NICs hash and re-customize.
- T024 writes status `unitNumber` from hardware when the policy is on; decide whether it should be written only with `VMNetworkUnitNumbers` (the CRD drops the field otherwise). With the policy on, primary IPs wait for a validated per-NIC Tools report (10–30 s per R1).
- Pre-existing spec 008 bug (not fixed here): with `VMNetworkUnitNumbers` on, `ActivatedFeatureVersion` includes `FeatureVersionNICUnitNumbers` but nothing sets it, so every reconcile stops at schema upgrade. The T018 vcsim test pre-sets the annotation as a workaround.
- Spec 008 G2/T021 text still describes Tools-only status entries; status.md says it must change with the revised `unitNumber` godoc (owner decision).
- Cleanup left for a follow-up: `CreateAndWaitForNetworkInterfaces` and `ListNetworkInterfaces` are used only by tests; some planner/builder parity tests are tautological now that `CreateVirtualEthernetCard` delegates to `BuildAdd`; no vcsim test runs a planned Add together with NIC tuning through `doReconfigure`.
